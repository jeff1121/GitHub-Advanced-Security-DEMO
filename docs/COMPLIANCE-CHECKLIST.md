# BingoBlitz — 合成憑證複核檢查清單

> **2026-09-11：流程草案已建立；T-005 尚未完成。** 第二人複核者尚未指定，也沒有接受角色的紀錄。
> 本文件僅記錄流程，不保存實際或合成 token 值。合成測試值清單應置於不進版控的受控文件。

## 不可妥協的界線

- 不使用任何真實憑證，包括已作廢、已輪替或來自測試訂閱的真實 Key。
- 優先評估供應商公開範例；引用時記錄官方來源、取得日期及非功能性依據。範例格式不代表 GitHub 一定會偵測。
- 自行生成的測試值須有可追溯的生成方式，使用合成資料與非真實資源，並由第二人複核。
- 不從使用者的 `.env`、CLI credential store、雲端帳戶或 CI Secrets 擷取素材。
- 目前只授權本地準備；不推送新合成秘密、不關閉或 bypass Push Protection。公開推送需另行授權及複核。

## 複核與證據清單

- [ ] 指定第二人複核者，記錄對方接受角色。
- [ ] 在受控、未版控文件建立測試值來源與生成紀錄；此 repo 只記錄場景 ID，不記錄清單內容。
- [ ] 複核者確認沒有真實憑證或真實資源資訊混入，並記錄對應 commit／檔案與結論。
- [ ] 公開推送前確認使用者授權範圍、目標分支及用途。
- [ ] 獲授權後再記錄 GitHub 實際偵測與攔截結果。沒有出現 alert，不代表測試值安全或已通過複核。
- [ ] 僅對支援 validity check 的 token 記錄實際結果；`unknown`／無法驗證不能作為「已證明無效」的依據。
- [ ] 若任何值被回報有效，立即停止演練，通知負責人依事件流程處理；不要繼續嘗試存取資源。

## 完成定義

T-005 需同時具備**完整檢查流程、受控來源清單，以及已接受角色的複核者**。僅有這份 Markdown 檔案不能標記任務完成；雲端 validity 檢核屬後續 T-403，不能用尚未執行的結果補足前置複核。
